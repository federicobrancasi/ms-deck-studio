# Design plugins

A design plugin is a one-off drawn page, filled from plain slide fields and used like a layout (`layout: 'gate'`). Long
talks lean on them: a different picture for almost every idea, all in the same tokens. The designs here are a catalog of
style and technique: a new deck should draw its own pictures (in `designs/local-<deck>.mjs`) rather than reuse these. They live in [designs/](../designs/);
the guide (level 3) and [examples/metaphors.mjs](../examples/metaphors.mjs) show them. `designs/guide.mjs` holds the
pages of the guide itself (`guide-cover`, `guide-levels`, `guide-anatomy`, `guide-pair`, `guide-swatches`,
`guide-typescale`, `guide-catalog`, `guide-strip`): use them to document your own kit.

A deck can draw every section divider with one design: `export default { ..., divider: 'divider-signpost' }`. The slides
keep `layout: 'section'`, so the minutes and the checks still treat them as dividers.

## The house style

The six designs people picked when three versions of the same deck were compared side by side ([designs/house.mjs](../designs/house.mjs)). [examples/front-desk.mjs](../examples/front-desk.mjs) uses all six in order.

| Design | What it draws | Fields |
| --- | --- | --- |
| `sieve` | A sieve: of 100 things, the ones that were caught sit as dots in a tray with a net for a bottom; the ones that slipped through lie as rings in a bin below, the last row still falling. One or two panels side by side, one per click (earlier panels stay bright). | eyebrow, title, kicker (small caps over the panels), panels (1–2): [{ name, value (0–100 caught), big (default 'value%'), label (e.g. 'caught'), tone }], caught: { title, icon } (the tray's label), missed: { title, icon } (the bin's label), caughtTone (default 'green'), missedTone (default 'red'). |
| `flow-bands` | How it works, as bands whose width is the share: a source, a node (with its questions as little marks), a first gate that sends part of the flow straight to a bottom outcome, a second gate that splits the rest between a top and a middle outcome; each outcome card shows its share big. Built in three clicks (node, gate 1, gate 2); every part stays at full strength once shown. | eyebrow, title, kicker (small caps, top left), source: { title, icon }, node: { title, sub, icon, marks (question marks, 0–14) }, gates (2): [{ title, yes, no }, { title, yes, no }], outcomes (3): [top, middle, bottom], each { title, share (0–100) }: gate 1 'no' goes to the bottom one, gate 2 'yes' to the top one and 'no' to the middle one. The shares set the band widths. |
| `fork-cover` | A cover with the idea drawn on the right half: a start (an icon in a circle) leads into one big node (an icon in a purple ring, its label under it), which forks into 2–4 end cards, the most important on top. The left is the built-in title: eyebrow, title, sub (one plain line), speaker, pills. | eyebrow, title, sub (or quote, for real words someone said), speaker: { initials, name, role }, pills, start: { icon }, node: { icon, label }, ends (2–4, top to bottom): [{ title, sub, icon, tone }]. |
| `dumbbell` | Before -> after per group, with a hierarchy: one row per group, a hollow grey dot (before) joined by a green bar to a filled green dot (after) on a 0–max scale, the gain on the right. Rows with hi: true (the few that matter) are at full strength, the rest muted. Rows with mark: true get a small grey marker, explained by one calm note under the chart (the honest caveat). | eyebrow, title, rows (4–12): [{ label, from, to, gain, hi, mark }], max (default 100), unit (default '%'), legend: { from, to }, mark: { icon, text }, axis (word at the scale's end). |
| `ladders` | One ladder per column: three rungs, bottom to top, each with a chip naming what sits there (null = not used, a dashed grey rung), the row names on the left, and the column's result as a giant number in a tile under it. | eyebrow, title, rows: [bottom, middle, top] (row names), columns (2–5): [{ name, rungs: [bottom, middle, top], value, tone (default 'green') }], caption (left of the results), unused (text on an unused rung). |
| `launch` | Next steps as a countdown to a launch, for a blue page (bg: 'blue'): white step cards numbered down along a dashed track that ends at a rocket waiting on its pad, engine not lit. | eyebrow, title, steps (3): [{ icon, title, sub }], pad (label under the rocket). |

## Props

Detailed frames for the devices and windows illustrated decks keep needing, in [src/props.mjs](../src/props.mjs) and
exported from `src/kit.mjs`. A prop is a frame, not a picture: it holds a real screenshot (`src`) or your own HTML
(`content`), or a placeholder screen if you give it neither, and draws the device around it with true proportions.
Each is placed at `(x, y)` in your design and sized by its width; it returns `{ html, w, h }` and the screen area, so
you can put callouts on top. Use props so devices look real, and spend your drawing time on the idea.

| Prop | Draws | Options |

| `laptop()` | a laptop: lid with a camera dot, 16:10 screen, a base with a lip and a thumb notch | x, y, w (640), src \| content, fit, pixelated → { html, w, h, screen } |
| `monitor()` | a desktop monitor: 16:9 screen, neck and weighted foot | x, y, w (720), src \| content, fit, pixelated → { html, w, h, screen } |
| `appWindow()` | an editor-style window: title bar, activity bar, sidebar (one row selected), main area, blue status bar | x, y, w (900), h, title, sideTitle, rows, selected, sidebar, activity, theme ('light' \| 'dark'), src \| content, fit → { html, w, h, main } |
| `browser()` | a browser: a tab, the address bar with a lock and the URL, the page | x, y, w (900), h, url, tab, src \| content, fit → { html, w, h, page } |

## Write your own

```js
// designs/my-designs.mjs
import { esc, fmt, ic, heading, body, bodyHeight, W } from '../src/kit.mjs';

export const designs = {
	/** What it draws, and its fields: eyebrow, title, items: [{ icon, text }]. */
	'stepping-stones': {
		css: `
.stepping-stones { position: relative; width: 1728px; }
.stepping-stones .ss-stone { position: absolute; border-radius: 50%; background: var(--blue-tint); }
`,
		render(s) {
			const H = bodyHeight(s);
			const stones = s.items.map((it, i) => `<div class="ss-stone" style="left:${i * 300}px;top:${H / 2}px" data-t>${fmt(it.text)}</div>`).join('');
			return heading(s) + body(`<div class="stepping-stones" style="height:${H}px">${stones}</div>`, { vcenter: false });
		},
	},
};
```

Draw with the shared helpers in `src/kit.mjs`, so every design has the same strokes, corners and text checks:

| Helper | What it does |
| --- | --- |
| `STYLE` | `{ stroke: 4, strokeBold: 6, radius: 20, radiusSmall: 12, gap: 24 }`: use these, not your own numbers |
| `t(cls, style, html, { tag, fit, nolint })` | a checked text element (overflow, overlap, safe area, words) |
| `at(x, y, w, h)` | an inline position style |
| `layer(h, svg)` | an SVG layer the size of the body, under the HTML |
| `band(x0, a0, b0, x1, a1, b1, fill)` | a ribbon from one span to another: flows sized by share |
| `mix(tone, pct)` | a tone mixed with white, for tints |
| `wob(i)` | a fixed wobble for a hand-placed look that never changes between builds |
| `logo(slug, size, color)` | a brand mark, to name a product or tool: `slack`, `github`, `githubcopilot`, `openai`, `anthropic`, `claude`, `python`, `x`, `youtube`, and `vscode` (not in the repo: drop its SVG at `theme/logos/vscode.svg`). Use it beside the name, never as decoration. |

Coordinates: a design that uses `heading(s) + body(...)` draws in body space (0–1728 × 0–694, less with a QR badge);
a `bare` design draws on the whole slide (0–1920 × 0–1080). Tones: put `t-<tone>` on an element and use `var(--fg)`
and `var(--tint)` inside it. `var(--yellow)` is the signpost and traffic-light yellow (never for text).

Rules the loader and the build enforce:

- **Every CSS selector names the design** (`.stepping-stones ...`), so two designs can never change each other's look.
- **No blurred shadows or filters**: macOS Preview draws them as grey boxes. Use a sharp ring (`0 0 0 4px`).
- **Every text element carries `data-t`** (checked for overflow, overlap and the safe area); a box that could overflow
  carries `data-fit`. Labels that are names, not sentences, add class `nolint` so the word count skips them.
- **Every visible word comes from the slide's fields**, with sensible defaults: a design is a picture, not content.
- Colours come from the tokens (`var(--blue)`, `t-green`), icons from `ic(name)` (Fluent), images from `asset(src)`.
- `bare: true` drops the header line and counter (for covers and closing cards).
- Don't read `s.minutes`: the build uses it as the slide's speaking time.
- **Clicks:** a design that draws its own clicks says `clicks: true` and reads `ctx.step` (1-based) and `ctx.steps`.
  On a slide without clicks (an options deck, a handout) `ctx.step` is `null`: draw the whole picture then
  (`const step = ctx.step ?? Infinity`), never an empty first state.
  Every element keeps its place on every click (`data-key`); on the last click show the whole picture at full strength.
- **Text on a drawn surface:** text on something painted in SVG (a white gear, a yellow plate) says what is under it
  with `data-on="#ffffff"`, so the contrast check on blue and dark pages reads it right.
- **Text inside a drawn shape** (a diamond, a tag) goes in an element with `data-shape` the size of the shape: the
  build flags text that spills out of it.
